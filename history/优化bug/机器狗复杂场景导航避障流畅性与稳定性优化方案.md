**机器狗复杂场景导航避障流畅性与稳定性优化方案**

整理日期：2026-11-04。

本文根据当前工程代码检查及本次讨论整理，适用于默认的 LIO + indoor + DWB 导航链路。文中的“当前值”指源码及 launch 覆盖后的默认配置，不代表已在线读取或确认实机正在使用这些参数。“建议”“目标”和“待实施”均为后续工作，本次仅保存方案，没有修改导航代码、参数或运行状态。

**一、目标与总体方向**

目标是在真实机身足迹允许、传感器观测可靠的条件下，实现复杂场景中的连续绕障、稳定窄道通过和有边界的自主脱困。流畅不等于始终保持高速：静态障碍且空间充足时尽量连续运动；突发障碍、观测失效或空间不足时可靠停车；条件恢复后有序继续或换路。

总体方法是：根据通道净空和机身姿态判断可执行动作，将步态能力、速度变化和碰撞约束共同纳入轨迹选择，减少下游反复压低速度以及控制模式反复切换。

针对狭窄地形，膨胀半径先维持当前基线。全局统一扩大膨胀半径不作为本方案的主要措施。后续如调整膨胀层，应作为可独立评估的路径偏好试验，同时验证狭窄通道的通过能力。

**二、当前系统与问题依据**

默认入口为 [scripts/run_lio_navigation.sh](scripts/run_lio_navigation.sh)，指定 `controller_mode:=dwb`、`terrain_mode:=indoor`。

| 环节 | 当前实现 |
|---|---|
| 定位 | HAP + FAST-LIO，导航使用连续坐标系 `odom_lio` |
| 全局规划 | `go2_navigation::ExactGoalSmac2D`，继承 SmacPlanner2D |
| 局部控制外层 | `go2_navigation::StableRotationShim` |
| 局部轨迹规划 | `dwb_core::DWBLocalPlanner` |
| 轨迹生成 | `go2_navigation::GaitTrajectoryGenerator`，继承 StandardTrajectoryGenerator |
| 障碍信息 | 原始投影扫描、去畸变扫描、地形图、独立障碍记忆 |
| 速度执行 | 速度平滑器、Collision Monitor、ScanSafetyGate、go2_base |

MPPI 已配置为可选控制器，默认入口选择 DWB。工程旧 README 中的 RPP 描述与当前入口不一致，诊断以实际启动和节点配置为准。

速度传递关系如下：

```text
StableRotationShim / DWB
    → /cmd_vel_nav
velocity_smoother
    → /cmd_vel
collision_monitor
    → /cmd_vel_safe
scan_safety_gate
    → /cmd_vel_guarded
go2_base
    → Go2 运动接口
```

当前现象：空旷区域运行正常，路线出现障碍后行走、转向变慢并发生抖动；RViz 中全局路线已经生成。

初步原因分为以下几类，不能仅凭代码确定本次现场问题由哪一项主导：

| 可能原因 | 影响与依据 |
|---|---|
| 上游步态约束与后级限速不一致 | DWB 排除低于 0.22 m/s 的非零平移候选，但后级仍可能进一步降低速度 |
| 全局路线与完整机身运动不一致 | 二维路线存在，不代表矩形机身能按当前朝向转弯通过 |
| 原地转向与弧线跟踪反复切换 | 原地转向受阻后交给 DWB，新路径到来又重新判断方向 |
| 数据过期造成停车脉冲 | 扫描、足迹、障碍记忆、里程计和速度指令有各自的新鲜度门槛 |
| 障碍观测或历史记忆改变可行空间 | 扫描稀疏、姿态与地面估计误差、动态障碍清除延迟等可能影响轨迹判断 |
| 运动候选受限 | 当前不采样横移、倒退，部分位置缺少可用脱困动作 |

已有历史日志 [navigation_standing_restart_20261104_100815.log](reports/navigation_standing_restart_20261104_100815.log) 出现过 `No valid trajectories out of 198!`、`Motion gate closed (scan=False, footprint=True, memory=True)`、扫描年龄超过 0.5 s 和 `Robot pose is stale during path alignment`。这些记录说明相关条件曾经触发，但不构成本次现场故障的唯一原因证明。

**三、狭窄通行的核心：位置、朝向与完整足迹共同判断**

当前名义足迹为长 0.76 m、宽 0.40 m，四周增加 0.07 m padding，保护矩形约为长 0.90 m、宽 0.54 m。这是当前配置模型，仍需与实际步态摆动、腿部外伸和机身附件核对。

对于理想的平行直通道，矩形机身与通道方向夹角为 θ 时，横向占用宽度近似为：

```text
横向占用宽度 = 0.54 × |cos(θ)| + 0.90 × |sin(θ)|
```

| 朝向误差 | 横向占用宽度 |
|---|---:|
| 0° | 约 0.54 m |
| 5° | 约 0.62 m |
| 10° | 约 0.69 m |
| 16° | 约 0.77 m |

因此，70 cm 通道在理想几何条件下可能允许对正直行，但不允许带较大角度进入。上述计算只解释几何关系，不是通行保证；实际判断还要计入测量、定位、步态和栅格误差。

待实施的判断与执行流程：

1. 从有效障碍数据估计入口、出口、通道方向、左右边界和净空，并评估观测可信度。
2. 依据完整足迹和误差余量，求当前通道允许的横向偏移与朝向范围。
3. 在入口外有旋转空间的位置完成必要对正，再进入通道。
4. 通道内优先居中直行，只允许经过完整足迹检查的小幅转向修正。
5. 出口转弯前检查足迹扫掠空间，避免前半身出通道后就开始大角度转向。
6. 对不规则障碍和窄弯使用完整多边形沿轨迹的碰撞检查，不能只用上述宽度公式。

前后朝向均纳入规划时，需要规划包含 `x、y、yaw` 的运动过程。初期可沿现有 Smac2D 路线增加姿态可行性检查与局部修整；连续窄弯等复杂工况再评估能够表达实际运动原语的完整姿态规划方案。

**四、按场景组织控制行为，减少无必要切换**

建议在现有控制器之上明确以下状态，并输出状态及切换原因用于诊断。状态名称为方案描述，当前代码尚未完整实现这些状态。

| 状态 | 主要行为 | 典型退出条件 |
|---|---|---|
| 普通路径跟踪 | 空间充足时平顺跟踪路线 | 前方出现需要绕行的障碍或狭窄入口 |
| 开阔绕障 | 选定绕行侧，连续执行安全弧线 | 绕过障碍、当前侧不可行或进入窄道 |
| 窄道入口对正 | 在入口外对正并检查通行姿态 | 朝向、位置、观测和前方空间满足进入条件 |
| 窄道通过 | 保持居中和低角速度，维持可执行步态 | 完全通过、出现新障碍或净空不足 |
| 调整与脱困 | 使用经检查的后退、横移或分段动作 | 到达可重新规划和转向的位置 |
| 停车等待 | 当前无安全动作或数据无效时停车 | 数据恢复、障碍离开或新路径可执行 |

切换规则：

- 同一目标的正常重规划保留有效的绕行侧与控制状态，避免每 0.5 s 重新开始对正。
- 通道进入和退出采用不同条件或确认窗口，减少净空测量波动造成的模式跳变。
- 对方向保持和动作切换设置合理偏好；只有当前动作不可行或另一方案明显更优时才切换。
- 启动、停止和转向切换使用可执行的速度过渡，实际输出轨迹逐周期检查。
- 状态保持不能阻止紧急制动；新障碍进入当前轨迹时立即响应。
- 停车、重试和脱困应有次数或时间边界，长期不可达时明确反馈原因。

**五、共同考虑步态、净空、速度和制动，消除低速试探**

当前 DWB 通过自定义生成器排除低于 0.22 m/s 的非零平移候选，纯转向相关最低速度配置约为 0.55 rad/s。它们是当前工程的设定值，需要通过实机校准确认，不能视为所有地面、负载和电量下不变的物理门槛。

现有后级按比例缩放会破坏上游对稳定步态的保证。例如：

```text
控制器期望：vx = 0.26 m/s，wz = 1.0 rad/s
近障碍角速度上限：0.65 rad/s
保持曲率按比例缩放后：vx ≈ 0.169 m/s，wz = 0.65 rad/s
```

这个例子说明仅角速度限幅就可能拉低平移速度；后面的预测制动还可能继续降低速度。这是算术与代码机制示例，不代表某次实机最终指令的完整计算结果。

待实施方案：

1. 校准直行、弧线、纯转向以及后续横移、后退各自的稳定速度区间、起步时间、加减速度和制动距离。
2. 将近障碍正常速度约束提前提供给轨迹生成与评分过程，控制器直接比较满足步态和安全条件的候选动作。
3. 根据轨迹方向上的真实净空、机身扫掠、观测年龄和实测制动能力决定速度上限。
4. 正常巡航阶段选择可持续的步态；起步和制动允许短暂经过低速区，但避免持续停留或反复重新起步。
5. 当前弧线不可执行时，选择另一条安全弧线、先对正、后退调整或停车重规划。
6. 最终安全层可以随时减速或停车；不得为维持步态而抬高未通过碰撞检查的速度。

沿运动方向的制动距离可用下式辅助理解和校准：

```text
所需距离约为 v × 响应延迟 + v² / (2 × 有效减速度) + 误差余量
```

实际转弯需检查整个足迹沿制动弧线的扫掠。参数使用实测有效值，不能只使用配置中的理想加速度。降低速度能缩短动态制动距离，但不能消除机身宽度、步态摆动和转弯空间需求。

**六、协调速度处理链，保留独立最终保护**

当前多个环节都可能限制速度。优化方向是让正常运动约束尽早进入控制器，后级负责平滑、独立复核和必要干预。

```text
真实障碍、通道净空、观测质量、步态能力
    → 统一提供正常运动约束
    → 局部候选轨迹生成、完整足迹检查与连续性评分
    → 速度平滑
    → 原始扫描与障碍记忆的独立安全复核
    → 最终底盘指令
```

具体要求：

- 对能表达为同一速度上限的约束求交集，减少重复的正常限速和反复爬升。
- 原始扫描、障碍记忆及定位健康仍保留各自的保护职责，只有经过等效性验证的重复计算才合并。
- 平滑或恢复斜坡如果改变曲率，需要检查最终实际下发的轨迹。
- 紧急停车不等待普通平滑器慢慢减速；正常恢复则按已验证的斜坡进行。
- 当前近障碍软限速函数可作为约束来源，逐步避免它成为控制器之后不可见的长期速度压缩环节。
- 在各级输出中保留来源、限制原因和变化量，便于判断哪一层首先产生抖动。

不能仅在最终输出端增加速度下限，也不能用持续低通滤波延迟真实危险引起的停车。

**七、障碍地图与膨胀层的处理原则**

区分三类信息：真实占用和机身碰撞边界、带测量不确定性的保护余量、引导路线远离障碍的软代价偏好。

Nav2 标准膨胀层的外侧渐变区域不等同于全部禁止通行，半径增大也不直接意味着通道最小宽度等于半径的两倍。但较高软代价仍会影响路线与局部评分，应结合实际规划结果验证。

当前阶段的安排：

- 保留现有足迹和 0.07 m padding，先核实实际步态包络与误差来源。
- 局部和全局膨胀半径先保持 0.30 m，缩放系数保持 8.0，作为对照基线。
- 需要改善开阔绕障路线时，再单独比较软代价参数，测试中必须包含窄道。
- 窄道通过依据完整足迹与轨迹净空，避免仅因代价较高就无条件判定不可达。
- 对实际不可通行、未知或观测不足的区域，明确区分原因；不能通过缩小真实足迹或将未知区域直接当作自由空间来通过。
- 若定位不确定性或观测延迟增加，应降低速度、改善观测或停车，不随意减小保护余量。

当前局部分辨率 4 cm、全局分辨率 8 cm。狭窄通道可能受到栅格量化影响。只有确认失败来自栅格表示后，再评估局部精细化或规划分辨率调整，并重新测量 CPU 和时延；不默认全局大幅提高分辨率。

**八、感知、障碍记忆与时延治理**

原始 `/scan_safety` 用于快速响应，去畸变 `/scan` 和独立障碍记忆提供其他几何证据。需要统一坐标、时间和障碍解释，减少同一障碍在不同链路中的位置差异。

主要工作：

1. 核对雷达外参、姿态调平、地面过滤和机器人自身点过滤，检查步态期间的近地误检。
2. 对照原始障碍点、扫描扩展后的障碍、记忆障碍和最终代价地图，区分真实障碍、投影变宽与残留记录。
3. 保留细杆、桌腿等真实障碍，依据可信证据处理噪声，避免简单增大去噪阈值。
4. 动态障碍离开后的清除依赖实际观测证据；盲区障碍保持，不使用统一 TTL 自动删除。
5. 优化新占用证据处理与发布，隔离重计算，限制陈旧队列，降低回调耗时和调度尖峰。
6. 检查 CPU 负载、DDS 接收、传感器时间戳、网口与物理连接，分开处理计算延迟和真正的数据中断。

建议以以下指标作为优化目标，最终以现场基线和测试结果确定：

| 指标 | 初始调试目标 |
|---|---|
| 15 Hz 控制周期的计算耗时 | P95 低于 50 ms，关注超过 66.7 ms 的周期及连续超时 |
| `/scan_safety` 消息年龄 | P95 低于 0.20 s，同时记录 P99 和最大间隙 |
| 障碍记忆消息年龄 | P95 低于 0.45 s，同时记录 P99 和最大间隙 |
| 静态、可通行绕障过程 | 无数据过期造成的反复安全门开关 |

这些是目标值，并非当前性能结论。先优化处理和传输，再评估预算；不通过改写旧数据时间戳或简单放宽过期门槛掩盖停顿。

**九、扩展横移、后退和自主脱困能力**

当前 DWB 的 `min_vel_x=0`、`max_vel_y=0`，行为树失败后主要等待重试，因此部分狭窄位置缺少调整动作。

扩展需要同时完成：

- 实测 Go2 对横移、后退及组合转向指令的执行响应和稳定步态范围。
- 检查对应方向的有效观测与障碍记忆覆盖，不能将未观察的后方或侧方视为可通行。
- 更新局部轨迹生成、运动模型、速度范围、平滑器以及底盘限制，保持一致。
- 检查现有前向观测要求、接近障碍预测和安全门逻辑是否适用于新的运动方向。
- 对完整机身沿横移、后退轨迹进行碰撞和制动检查。
- 将脱困动作纳入有次数和时间边界的行为流程，并保留随时停车条件。

因此，启用横移、后退不只是把 `max_vel_y` 或 `min_vel_x` 改成非零。

**十、DWB 与 MPPI 的选择**

第一阶段保留 DWB，先处理可观测性、步态约束、限速一致性、窄道姿态和模式切换。DWB 当前 Critic 权重不作为第一批随意调整项，应先统计无效轨迹原因与各项评分贡献。

只有在上述问题得到控制后，仍出现候选轨迹表达能力不足或复杂绕障连续性不足，再以相同场景比较 MPPI。比较时统一足迹、感知、安全门、速度上限和目标条件，测量成功率、平顺性、净空和计算耗时。

更换局部控制器不替代完整姿态规划，也不自动解决后级限速和数据过期。控制器选择以可重复实测结果决定。

下表用于后续实施时对照。可选试验值尚未应用，不代表最终推荐值。

| 扫描过期门槛 | 0.35 s | 保留，优先降低链路延迟 |
| 足迹过期门槛 | 0.50 s | 保留 |
| 障碍记忆过期门槛 | 0.75 s | 保留 |
| 安全门输入指令超时 | 0.20 s | 保留，检查上游输出连续性 |

试验速度上限应同步修改局部控制器和速度平滑器，并检查自定义软限速、转向控制和底盘上限是否一致。较低巡航上限的目的在于评估速度变化与连续性，不能据此假定所有窄道都能通过。

**十二、实施顺序与完成条件**

每阶段形成单独变更和可回退配置，避免同时修改大量参数后无法区分原因。

| 阶段 | 工作内容 | 完成条件 |
|---|---|---|
| 1：建立基线 | 同步记录四级速度、实测运动、定位、扫描、足迹、记忆和安全诊断 | 能把主要停车或抖动片段归因到具体环节 |
| 2：治理时延 | 优化重计算、排队与发布，排查传感器和网络中断 | 静态可通行场景不再因数据过期反复停车 |
| 3：联合运动约束 | 将正常近障碍速度和稳定步态约束前移，检查实际下发轨迹 | 减少持续低速试探，安全制动仍及时有效 |
| 4：稳定动作选择 | 保持有效绕行侧，改善原地对正与弧线切换 | 同一障碍绕行无无理由的反复换向和重对正 |
| 5：窄道通行 | 增加净空、入口对正、居中跟踪、出口扫掠检查 | 能解释并稳定处理可通行与不可通行窄道 |
| 6：复杂转弯与脱困 | 完整姿态可行性验证，按观测与实测能力扩展横移和后退 | 狭窄受困位置可有限次恢复，失败原因明确 |
| 7：控制器与性能比较 | 必要时比较 DWB、MPPI 及规划表达能力 | 依据同场景指标确定最终方案 |

参数试验安排在基线记录后，作为单独 A/B 变更，不与核心逻辑修改混在同一次比较中。

**十三、验收场景、记录指标和判断方式**

| 场景 | 主要检查点 |
|---|---|
| 空旷直行及普通转弯 | 保持现有基本能力，指令与实测响应一致 |
| 单箱绕行 | 提前选边，弧线连续，无非必要停车 |
| 连续交错障碍 | 能有序切换绕行方向，避免局部左右摇摆 |
| 桌腿、细杆、低矮障碍 | 保留真实障碍，不以漏检换取流畅 |
| 不同宽度的直通道、门框 | 可通行时对正通过，不可行时原因明确 |
| 窄道斜向入口 | 在入口外完成姿态调整，避免边进入边大角度转向 |
| L 形、S 形窄弯 | 检查完整机身扫掠，必要时分段调整 |
| 行人横穿与突然进入 | 制动及时，恢复有序，动态残留有证据清除 |
| 通道被堵、死胡同 | 有边界的等待、换路或脱困，避免无限重试 |
| 扫描、定位、记忆短时失效 | 可靠停车，恢复条件符合设计 |

各场景在固定起终点、固定障碍布局下重复运行，记录地面、负载、电量与额外计算负载。静态与动态场景分开统计，避免将必要停车计作流畅性失败。

主要记录指标：

- 成功率、任务耗时、行驶距离及失败原因。
- 静态可通行段的非必要停车次数和停车时长。
- 选定绕行侧后的无必要转向反复；S 弯等正常换向单独标记。
- 最终指令持续处于实测不稳定步态区间的时长，起停过渡单独标记。
- 实际机身与障碍的最小净空、横向偏差和通道内朝向误差。
- 速度、角速度及其变化，与实测运动之间的响应关系。
- 数据年龄 P50/P95/P99、最大间隙、计算耗时及安全门关闭原因。
- 突发障碍响应、停车距离和停止后恢复行为。

完成条件不是单次成功，而是在重复测试中减少非必要停顿和摆动，保持可通行窄道通过能力，并保持真实障碍、观测失效和不可行路径的可靠处理。

**十四、定位具体限制环节的记录接口**

| 观察结果 | 优先定位环节 |
|---|---|
| `/cmd_vel_nav` 已反复为零或无理由换向 | DWB 候选、评分、无有效轨迹及 StableRotationShim 切换 |
| `/cmd_vel_nav` 连续，`/cmd_vel` 明显变化 | 平滑器速度、加速度、死区、超时与曲率缩放 |
| `/cmd_vel` 连续，`/cmd_vel_safe` 明显降低 | Collision Monitor 停车区和预测碰撞 |
| `/cmd_vel_safe` 连续，`/cmd_vel_guarded` 降低或归零 | 最终安全门、记忆障碍、扫描与足迹新鲜度 |
| 最终指令正常但实测运动很小、身体抖动 | Go2 步态执行、底盘反馈和物理响应 |

重点诊断话题为 `/safety/motion_diagnostics`、`/safety/obstacle_memory_status`、`/lio/localization_valid`、`/go2/motion_execution_valid`。同时记录 `/odom` 和 Go2 实测状态，区分定位速度估计与真实运动反馈。

安全门重点字段包括：`input`、`output`、`caution_scale`、`approach_braking_scale`、`memory_approach_scale`、`recovery_check_scale`、`turn_clear`、`hard_zone_clear`、`scan_valid`、`footprint_valid`、`memory_valid`、`command_fresh` 及各消息年龄。

这些缩放字段描述不同阶段，不能直接全部相乘解释最终输出；还需结合恢复斜坡和最终复核。空闲或目标结束后的零指令，也不能单凭诊断中的零比例判断为障碍误停。
