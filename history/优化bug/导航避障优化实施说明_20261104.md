**导航避障优化实施说明（2026-11-04）**

本轮已修改并构建当前 `FISH_ws` 的导航代码，重点处理近障碍速度重复缩小、窄道入口姿态、弧线交接反复切换和诊断不足。没有重启正在运行的实机导航，没有发送实机目标或底盘运动指令。

原始文件及校验信息保存在 [备份目录](backups/before_navigation_fluency_20261104_150141/manifest.json)。当前工作区没有可用的 Git 元数据，因此采用文件备份和独立构建目录。原始 `HAP_ws` 的代码与安装目标没有修改。

本轮结果适用于默认的 LIO + indoor + DWB 链路。它不是对所有复杂地形的实机通过保证；完整姿态全局搜索、横移／后退脱困与步态实测标定仍是后续工作。

**一、已经实施的改动**

| 改动 | 具体行为 | 主要文件 |
|---|---|---|
| 近障碍速度约束前移 | DWB 生成候选轨迹后，先由 `GaitSafety` 检查步态与净空速度范围，再参与后续评分；减少选中后又被安全层长期压成低速的情况 | [gait_safety_critic.cpp](ros2_ws/src/go2_navigation/src/gait_safety_critic.cpp) |
| 指令连续性偏好 | 在同一目标的连续计算中，对不必要的速度突变与转向反复增加软代价；碰撞约束仍可淘汰原方向并选择新方向 | 同上 |
| 窄道足迹评分 | 只有检测到有连续双侧墙体证据、且路线进入其中的可通行窄道时，抑制角点对软膨胀代价的重复计分；普通绕障保留原角点净空偏好 | [collision_footprint_critic.cpp](ros2_ws/src/go2_navigation/src/collision_footprint_critic.cpp) |
| 窄道姿态辅助 | 从局部障碍估计通道轴向及净空，结合保护矩形长宽计算朝向容许范围，在入口外尝试对正 | [motion_geometry.hpp](ros2_ws/src/go2_navigation/include/go2_navigation/motion_geometry.hpp)、[stable_rotation_shim.cpp](ros2_ws/src/go2_navigation/src/stable_rotation_shim.cpp) |
| 明确不可通行反馈 | 检测到通道净空小于保护矩形最小横向宽度，且当前路线确实进入该区域时，反馈控制失败；通道前的短距离目标仍可到达 | 同上 |
| 弧线交接保持 | 原地对正受阻后，有效的平移弧线可以跨同一目标的重规划保留；仅原地旋转的无效交接不会永久锁定 | 同上 |
| 转向结束前制动 | 在接近对正角度前考虑剩余角度与控制周期，允许短暂降到最低巡航转速以下完成制动，减少越过目标角度后的反复修正 | [rotation_helpers.hpp](ros2_ws/src/go2_navigation/include/go2_navigation/rotation_helpers.hpp) |
| 路径采样修正 | 从机器人附近的路径点按弧长前视，不再一直从旧路径起点取样 | [stable_rotation_shim.cpp](ros2_ws/src/go2_navigation/src/stable_rotation_shim.cpp) |
| 近终点速度一致性 | 最后接近目标的弧线同样先考虑近障碍线速度、角速度上限，再进行足迹检查 | 同上 |
| 近终点小角度修正 | 当限速后的弧线无法进入目标容差圆时，使用与剩余修正角度匹配的对正阈值，避免在目标容差外因普通路径对正阈值过大而持续输出零速度 | [rotation_helpers.hpp](ros2_ws/src/go2_navigation/include/go2_navigation/rotation_helpers.hpp)、[stable_rotation_shim.cpp](ros2_ws/src/go2_navigation/src/stable_rotation_shim.cpp) |
| 几何缓存与诊断 | 扫描、记忆、接受位姿均未改变时复用几何转换；每个控制周期仍检查新鲜度和碰撞，新增停车原因、停车脉冲和处理耗时 | [reactive_safety.py](ros2_ws/src/go2_lio_navigation/scripts/reactive_safety.py)、[scan_safety_gate.py](ros2_ws/src/go2_lio_navigation/scripts/scan_safety_gate.py) |
| Python 退出清理 | 安全门和障碍记忆节点由 Python 处理 Ctrl+C，先退出执行器、释放节点及工作进程，再关闭 ROS context，减少退出时的取消息竞态 | [obstacle_memory.py](ros2_ws/src/go2_lio_navigation/scripts/obstacle_memory.py)、[scan_safety_gate.py](ros2_ws/src/go2_lio_navigation/scripts/scan_safety_gate.py) |

`GaitSafety` 使用与当前安全门一致的近障碍软限速规律：近距离行走上限约 0.26 m/s，角速度上限约 0.65 rad/s，随净空增加逐渐恢复。局部栅格单元的几何范围也纳入上游估计。最终安全门仍独立检查原始扫描和障碍记忆；新障碍、动态接近或制动空间不足时仍可减速或停车。

指令连续性是软偏好，不是禁止换向。它不允许原本不安全的轨迹继续运动，也不会在最终输出端将低速度直接抬高到步态门槛。

**二、窄道策略与边界**

双侧墙体识别使用沿路径方向的分段证据，要求至少约 0.6 m 连续支持，并限制两侧边界变化。单个回波、单侧墙和明显发散的转角不会仅凭“障碍很近”进入该模式。

保护矩形维持约 0.90 × 0.54 m。窄道允许朝向根据机身横向投影计算，而不是统一使用普通对正的约 16° 退出阈值。模式短时保持只影响运动偏好；实际碰撞检查继续使用当前地图和当前扫描。

标准 Nav2 足迹碰撞拒绝仍执行，软代价处理只改变合格轨迹之间的偏好。普通开阔绕障保留角点净空评分，避免为改善窄门而削弱绕大障碍时的间距。

这是一项局部姿态辅助与候选评分改进。全局规划仍为 `ExactGoalSmac2D`，没有实现完整的 `x、y、yaw` 全局搜索，也没有把启发式通道识别当作未观测区域可通行的证明。栅格量化、定位误差、步态摆动和实际附件尺寸仍会影响窄道能力。

**三、参数与接口**

新增参数位于 [nav2_params.yaml](ros2_ws/src/go2_navigation/config/nav2_params.yaml) 的 `controller_server.ros__parameters.FollowPath` 下。

| 参数 | 值 | 用途 |
|---|---:|---|
| `corridor_alignment` | true | 启用窄道姿态辅助 |
| `corridor_max_width` | 1.20 m | 双侧墙体窄道识别宽度上限 |
| `corridor_margin` | 0.02 m | 朝向辅助计算的附加余量，不替代原有足迹 padding |
| `GaitSafety.class` | `go2_navigation::GaitSafetyCritic` | 速度与连续性 Critic |
| `GaitSafety.scale` | 3.0 | 指令连续性软代价权重 |
| `GaitSafety.minimum_translation` | 0.22 m/s | 非零平移候选最低速度检查 |
| `GaitSafety.history_timeout` | 0.50 s | 指令历史有效期；目标明显改变也会重置 |
| `ObstacleFootprint.class` | `go2_navigation::CollisionFootprintCritic` | 依据双侧墙体证据处理窄道软代价 |

`ObstacleFootprint.scale` 保持 2.0，并保持非零，以保证 DWB 执行该碰撞检查。原有 Critic 顺序中增加了优先执行的 `GaitSafety`。

以下重要基线保持原值：

| 项目 | 当前值 |
|---|---:|
| 原始足迹／padding | 0.76 × 0.40 m／0.07 m |
| 局部／全局膨胀半径 | 0.30／0.30 m |
| 局部／全局分辨率 | 0.04／0.08 m |
| 最大前进／角速度 | 0.65 m/s／1.4 rad/s |
| 最低稳定行走候选配置 | 0.22 m/s |
| 最低路径对正巡航转速配置 | 0.55 rad/s，起停过渡可短暂更低 |
| 控制／平滑频率 | 15／50 Hz |
| 扫描／足迹／记忆过期门槛 | 0.35／0.50／0.75 s |
| 安全门速度输入超时 | 0.20 s |
| 目标位置容差 | 0.10 m，最终朝向不限制 |

没有统一扩大膨胀半径、缩小真实保护足迹、放宽数据过期门槛，或启用未标定的横移和后退。

新增诊断话题：

| 话题 | 内容 |
|---|---|
| `/navigation/controller_diagnostics` | 当前控制模式、通道检测、净空宽度、朝向容许值及控制指令 |
| `/navigation/trajectory_diagnostics` | 当前软速度上限、候选数量、被速度约束淘汰的数量及选中指令 |
| `/safety/motion_diagnostics` | 原有字段加 `stop_reason`、`stop_pulses`、`input_moving`、`step_ms` 和 `max_step_ms` |

停车原因区分扫描、足迹、记忆、指令超时、足迹占用、制动弧线、预测接触、稀疏前向观测与恢复斜坡。空闲零指令不直接等同于障碍误停。

[只读试验记录器](scripts/record_navigation_trial.py) 已包含新增诊断话题，继续只记录用户发出的目标与运动，不发送目标或运动指令。

**五、验证结果与解释**

专项用真实 Nav2 控制服务器、平滑器、碰撞监控和安全门运行合成闭环世界；机器人位置由最终指令积分，并独立检查保护矩形与障碍的交叉。该模型没有 Go2 的真实步态、滑移和执行延迟。

已取得的功能结果包括：

- 125 项 LIO Python 单元测试、9 项导航 Python 单元测试及 29 项 C++ 用例通过；C++ 用例分为 6 个测试套件。
- 72 cm 平行直通道，从约 10° 朝向误差开始，在 2 Hz 路径刷新下完成入口对正与连续通过。一次记录约 8.8 s、17 次路径刷新，通道中段最低指令速度为 0.26 m/s，没有巡航零速度脉冲。
- 当前 54 cm 保护宽度无法通过 50 cm 通道时，明确反馈失败，避免持续原地试探；通道前的 20 cm 短距离目标仍可到达。
- 扫描停止后，安全门按原门槛停车；扫描恢复后能够恢复并到达目标。几何缓存不会替代每周期的新鲜度判断。
- 单个新回波进入保护区域时，合成扫描测试约 80 ms 发出停车指令。
- 近距离宽障碍绕行到达原目标，记录到约 0.28 m 的保护足迹净空；后方及第二个反向目标均完成，位置误差位于原 10 cm 容差内。
- C++ 回归覆盖窄道几何、角速度终端制动、近终点小角度修正、速度约束、同目标连续性、软代价与硬碰撞区分、未知区域和地图边界拒绝。
- 原有障碍记忆测试继续检查盲区保留、移动目标清除、细腿保留、checkpoint 恢复和记忆进程失效停车。

这些数值是隔离测试记录，不是实机同等时延、净空或速度承诺。最终检查的完整输出保存在 [navigation_fluency_full_regressions_final.log](reports/navigation_fluency_full_regressions_final.log)。专项场景每次还会生成独立的 `reports/navigation_fluency_时间戳/`，包含各节点日志、指令轨迹与结果 JSON。

近终点边界修正后的定向复测见 [navigation_fluency_goal_fix_check.log](reports/navigation_fluency_goal_fix_check.log)：两个反向目标分别以约 5.6 cm／8.8 cm 误差到达；72 cm 通道用时约 8.9 s，17 次路径刷新，巡航最低速度 0.26 m/s；单回波停车约 85 ms。该复测的 `rear_goals` 阶段仍因原生容器退出超时被严格判为失败，功能到达与退出错误分别记录。

最终完整复测的逐阶段日志见 [navigation_regressions_R8TmnOrC](reports/navigation_regressions_R8TmnOrC)：16 个阶段中 12 个通过，4 个因原生容器退出崩溃或超时被判失败，分别为 `obstacle_memory`、`mixed_crossing`、`obstacle_pipeline`、`rear_goals`，这 4 个阶段的功能检查命令均返回 0。最终宽障碍绕行位置误差约 5.7 cm，保护足迹净空约 0.28 m；往返目标误差约 6.6 cm／9.7 cm；72 cm 通道约 8.8 s，17 次刷新，巡航无停车或低速试探；单回波停车约 83 ms。最终窄道场景日志及轨迹见 [navigation_fluency_20261104_162357](reports/navigation_fluency_20261104_162357)。

**六、仍存在的独立问题与实机边界**

严格完整回归仍需单独看进程退出状态：当前安装的 Humble Nav2 组合容器在部分测试完成后接收 SIGINT 时，存在原生退出崩溃或关闭超时。此问题在本轮修改前的 [系统审查记录](reports/systematic_code_audit_20261104.md) 中已经记录。

本轮确认导航功能检查成功不代表退出路径正确；回归脚本继续将原生子进程非零退出、关闭超时和 Python Traceback 判为失败，不将完整回归表述为全绿。退出问题尚未定位到可验证的原生修复，本轮保持原组合容器配置。

后续实机重点验证：

1. 不同地面、负载、电量下的最低稳定行走／转向速度、起停响应和实际制动距离。
2. 真实附件、腿部摆动和定位不确定性是否被当前保护矩形充分覆盖。
3. 实际 HAP、FAST-LIO、地图、UI 同时运行时的处理耗时、扫描年龄与短时中断。
4. 不同宽度门框、窄道斜向入口、连续障碍及 L／S 形窄弯。
5. 需要后退、横移才能通过的场景；这些动作尚未启用，需要方向观测、轨迹模型与底盘标定共同支持。

完整姿态全局规划和自动脱困没有被本轮局部改动替代，不能据此宣称已覆盖任意复杂地形。
