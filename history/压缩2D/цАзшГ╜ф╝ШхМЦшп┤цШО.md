# Go2 建图与导航性能优化说明

## 优化目标

本轮针对“地图重影、刷新越建越慢、导航转弯过冲、板载 CPU 被高频消息占满”进行复查。
默认配置定位为室内中小型场地的“精度与实时性平衡”档，而不是单纯把所有频率调高。

## 关键变化

| 链路 | 原实现 | 优化后 |
|---|---|---|
| 点云累计 | 最近 30 帧每次全部重拼接，并把同一结果重复发布到 50 Hz | 固定坐标系内累计 3 帧、预分配内存，每个新 LiDAR 帧只发布一次 |
| 异常坐标系 | 无检查，移动坐标系累计会产生拖影 | 非固定坐标系自动退回单帧并报警 |
| 时间同步 | 位姿改写为回调到达时间，点云保留采集时间 | 两者统一使用 LiDAR 采集时间，拒绝乱序消息 |
| 四足步态 | roll / pitch / z 直接进入 2D 导航 TF | 默认平面化 `odom -> base_link`，隔离机身周期起伏 |
| LaserScan | 约 0.5°、标称 0.25 s、队列 30 | 约 0.4°、标称 0.10 s、队列 3，减少延迟 |
| SLAM 栅格 | 5 cm | 4 cm |
| `/map` | 参数要求 10 Hz 全图重算，容易实际阻塞 | 可持续约 2 Hz；兼顾刷新与扫描匹配线程 |
| 扫描匹配 | 普通平方损失 | Huber 鲁棒损失，降低动态物体/离群点影响 |
| AMCL | 90 束、20 cm / 0.2 rad 才更新 | 120 束、8 cm / 0.08 rad 更新，概率似然场 + beam skip |
| 点云 TF | 额外等待 0.5 s 未来变换、队列 10 | 使用精确采集时刻、队列 3，不制造固定滞后 |
| 局部代价地图 | LaserScan 仍经过 3D VoxelLayer | 直接使用 2D ObstacleLayer，10 Hz 更新 |
| 控制器 | DWB 多轨迹采样 | Regulated Pure Pursuit，20 Hz 控制 / 25 Hz 平滑，主动碰撞预测和弯道降速 |
| Qt | 高频位姿逐条触发重绘，地图逐格 Python 转换 | 位姿/绘制限制 20 Hz，OccupancyGrid 使用原始缓冲快速转换 |

## 实机检查

重新构建后运行：

```bash
bash scripts/build.sh
bash scripts/run_mapping.sh
```

另开终端：

```bash
bash scripts/benchmark_topics.sh 10
```

重点确认 `/trans_cloud` 和 `/scan` 接近 LiDAR 源频率，`/map` 约 2 Hz，且频率不会
随着地图增大持续下降。请再用 `htop` 观察是否有单核长期 100%。

## 根据板卡调整

- 如果 `/scan` 明显跟不上输入，把 `accumulation_frames` 从 3 降为 2；这比降低
  `/scan` 更新率更不容易引入控制延迟。
- 如果地图范围超过约 50 m × 50 m 且 `/map` 更新开始抢占扫描匹配，将
  `map_update_interval` 从 0.5 调成 1.0；定位精度不会因此下降，只降低界面全图刷新频率。
- 如果墙面太薄或断裂，先标定点云高度区间和 TF，再考虑把 SLAM 分辨率改成 0.03；
  不建议直接使用 0.02，因为内存和全图刷新成本会显著增加。
- `robot_radius: 0.35` 只是默认保守值。测量机器狗带全部外设后的真实外廓并改成
  `footprint`，对狭窄通道的可通过性和碰撞精度提升最大。

所有运动速度仍需在现场低速验证。首次测试应把机器狗架空或置于宽阔无人区域，
原厂遥控器急停始终是最高优先级。
