# SDK 基础人体跟随

入口为 `bash scripts/run_person_follow.sh`，不加载 ROS 环境、不启动 LIO/Nav2，
不依赖雷达在线。默认使用兼容 USB 2 的 D435i 左红外 + 深度双流，640×480、30 FPS，
预览为灰度图。本机实测原 640×480 彩色视野约 55.5°×43.0°，左红外约
78.7°×63.1°，低机位下可看到更多人体区域。保留 `--camera-view color` 使用原彩色模式。
通过 SDK 回调采集同步图像，人体检测复用已有 YOLOv8n CUDA 进程，
机身姿态从 Unitree SDK 的 `rt/sportmodestate` / `rt/lf/sportmodestate` 订阅，
任一路新鲜反馈均可使用，速度由现有 SDK 隔离进程下发。
使用已有相机到机身的标定文件，标定中的 `livox_frame` 只是固定安装坐标，
无需连接 Livox 驱动或查询 TF。
红外模式使用设备内参及红外/深度到彩色的出厂外参，先转换到原彩色光学坐标，
再使用现有机身安装标定；不会将红外坐标直接当作彩色坐标。

## 启动和操作

### UI 入口

启动 `bash scripts/run_ui.sh`，在首页点击「人体跟随」。原彩色采集会暂停，界面切换为
已验证的广角红外预览，主画面显示人物框、测距点和中心线，右侧继续显示同一相机的深度。
检测就绪后，在右下控制面板设置速度上限、跟随距离，再点击「开始跟随」。默认参数为
0.35 米/秒、1.5 米，单次最多 120 秒，运动期间参数不可更改。

「停止跟随」停车并保留预览，可以重新开始；「停止当前功能」退出并恢复彩色/深度双流。
切换语音、手势或视觉时，会等待跟随停止和相机释放后再开启下一项。进入导航前必须完成
退出；关闭窗口也会等待资源释放。模型加载在后台，停止请求不会等待模型加载完成才发出。
离线测试入口只能预览，不启用跟随运动。

UI 与独立入口共用相机互斥锁，不能同时运行；UI 运行日志位于 `log/ui_runtime.log`。
UI 直接复用 `PersonFollowController`、`FollowCamera` 和人物检测进程，不创建额外 OpenCV 窗口，
跟随控制、速度上限、深度处理及保护逻辑与实机已测试的独立版相同。

### 独立入口

先关闭交互 UI、导航、手势和其他机器狗运动控制程序，相机只能由一个程序占用。
沿用 `go2_jiaohu/.env` 中的网卡和模型配置，要求 `GO2_MOTION_BACKEND=sdk`。
无需运行依赖安装脚本或重新编译 ROS 包。

```bash
cd /home/fishbone/FISH_ws
bash scripts/run_person_follow.sh
# 显式指定默认跟随速度上限 0.35 米/秒
bash scripts/run_person_follow.sh --speed 0.35
# 只验证画面和人物检测，空格也不会触发运动
bash scripts/run_person_follow.sh --preview-only
# 对比原彩色视野（仍然只预览）
bash scripts/run_person_follow.sh --preview-only --camera-view color
# 可选：保持 1.5 米，最高 0.15 米/秒，每次运行最多 120 秒
bash scripts/run_person_follow.sh --distance 1.5 --speed 0.15 --duration 120
```

- 默认只有相机和检测预览，不连接 SDK、不下发运动。窗口需获得键盘焦点。
- **空格**：启动跟随；启动时画面必须只有一个清晰人物，并且机器狗已站稳。
- **S / Esc**：停止跟随，保留预览。Esc 不退出窗口。
- **Q / 关闭窗口 / Ctrl+C**：停止并释放相机、检测器和 SDK 进程。
- 漏检、单帧失配或测距不确定时立即下发零速度，最多等待约 1 秒。
  较长遮挡后必须连续两帧通过原目标的位置、深度和外观确认才恢复。
  持续丢失、身份不确定、遮挡交叉、深度不足、障碍或超时后结束本次跟随，需重新按空格。

绿色点是实际参与距离估计的前景深度采样，黄色框是人物框。终端显示中文状态和
停车原因；窗口显示距离和下发的速度。停止后窗口回到 `PREVIEW`。
启动时会依次输出窗口创建、相机启动、首帧到达、人物检测就绪的提示。
模型在后台加载，加载期间窗口显示实时画面和 `LOADING DETECTOR`，空格不会启动运动。
预览按平地、机身高 0.25 米估计地面，可通过 `--preview-height` 调整；这仅用于
未连接 SDK 的显示，不作为运动授权。跟随时必须有实时 SDK 姿态反馈。

## 测距与控制

人体框内按深度分组，结合当前姿态和安装标定剔除地面。保留有足够面积、竖直跨度
且主要落在人体框内的深度连通区域，再对这些点估计位置。
腿缝里的大面积背景墙、孤立近点不直接参与测距；绿色点应落在实际腿部/人体表面。
这是深度前景提取，并非人体部位语义分割，不能保证复杂背景中始终正确。

距离定义为 **base_link 原点到可见人体表面的水平距离**，包含相机安装偏移，
并不是到躯干中心或到机器狗最前沿的距离。预览和运动使用同一定义。
目标范围为 0.45–4 米，设定跟随距离为 1–2 米，默认 1.5 米。
深度分组优先选择接近上一帧确认距离的有效前景，避免突然选中腿缝背景或孤立近物。
关联时的距离变化容差为 `0.30 + 0.8 × 确认间隔秒数` 米，上限 0.80 米；超出时
本帧不授权移动，停车等待重确认，不会用远处背景直接续发速度。

采用短时平滑、距离死区和 0.60 米/秒² 起步加速度限制；默认最高 0.35 米/秒，
`--speed` 可设 0.05–0.40 米/秒，仍受 SDK 配置速度上限约束。
距离足够近时停止前进，继续调整朝向；目标再次走远后恢复前进。
转向以人物框相对画面水平中心的误差为准，偏角达到 1.2° 开始修正，回到 0.6° 内停止，
避免在中心附近来回抖动。采用比例/积分控制，修正时加入 0.22 弧度/秒的起转补偿，
最大角速度保持 0.50 弧度/秒。这个补偿值需要通过实机响应验证，不代表已标定的硬件阈值。
由 IMU yaw 变化估计实测转速，接近中心且正在收敛时提前收转，降低惯性过冲。
不再把 SDK 上报转速直接累加为目标移动前馈，避免前馈偏差使转向长期饱和。
目标到距后仍持续对准。偏角超过 5° 时降低前进速度，达到 12° 时停止前进，先转向居中，
超过 45° 时结束任务。不后退，不在目标丢失后盲目旋转搜索。
窗口中的青色竖线标记水平中心，紫色点和连线显示人物框中心及横向偏差。
这里跟随的是人物移动方向；人物仅原地改变身体朝向时，当前检测器不会识别其朝向。
距离取样来自腿部有效深度，朝向使用人物框中心对应的已知前景距离，避免左右腿
采样点数量变化引起转向抖动。人物关联融合运动预测、深度连续性、框重叠和灰度外观，
以小步更新外观模板，应对转身、红外曝光变化和全身/局部框切换。多个候选评分接近时
停车等待。支持红外图像，不提供人员重识别。跟随检测阈值为 0.35，原人物靠近功能仍为 0.55。

前方深度用于检查短距离转弯通道和地面，遇障停车，不规划绕行。
RGB-D 在发指令时必须新于 200ms，SDK 姿态必须新于 300ms。
每条速度指令使用原有 250ms 租约，感知中断后不再续期，由 SDK 进程执行停车。
投影缓存 SDK 校准射线，批量计算三维位置；本机进程冲突检查最多每 250ms 全量执行一次。
跟随期间每秒输出距离、偏角、vx/wz、SDK 上报转速、IMU yaw 推算转速和各阶段耗时，
便于区分“已下发转向”与“底盘实际转动”。倾斜停车附带实际 roll/pitch，原姿态门限保留。
日志同时轮转保存在 `log/person_follow.log`。超时与控制源冲突分开报告。
200ms 图像新鲜度门限保持不变。
单次时长默认 120 秒，可设置 1–600 秒；到时需手动重新开始。

本版本适合平整、开阔环境中的单人慢速跟随。相机视野无法覆盖全部机身周边，
不适合窄道、大角度急转、台阶或正常步行速度的跟随。

## 验证

先只使用预览：人在 1、1.5、2 米处站立和缓慢行走，检查绿色点是否落在腿部，
腿缝和背景是否被排除，观察测距是否随迈腿明显跳变。再在开阔场地低速验证启动、
停止、丢人停车和障碍停车；保留遥控器急停手段。

离线测试不启动相机、DDS 或真实运动：

```bash
cd go2_jiaohu
PYTHONNOUSERSITE=1 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
  ../.venv/bin/python -m pytest tests/test_person_follow.py \
  tests/test_person_follow_camera.py tests/test_person_follow_reactivity.py tests/test_person_follow_tracking.py \
  tests/test_sdk_follow_state.py \
  tests/test_visual_velocity_lease.py tests/test_sdk_worker.py -q
```
